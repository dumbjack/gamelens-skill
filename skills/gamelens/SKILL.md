# GameLens

按本次任务把游戏录屏转为带证据的结构化记录。图片是可复用的分析资产；Excel、HTML 和演示只是这些资产的使用方式。固定的是证据可追溯；拆什么、保留哪些图片、采用哪些字段由本次需求决定。

## 先适配本次任务

- 开始前读取 [任务适配规范](references/task-adaptation.md)，从用户要求与实际参考材料确定分析目标、范围、拆解单位、字段映射、图片清单、证据要求和交付形式。简短任务用行动记录概括即可，复杂或需复用的任务可保存为 `analysis_spec.json`；无需每次向用户索要一整套参数。
- 拆解单位可以是关卡、回合、任务、战斗阶段、操作事件、系统/界面或用户自定义对象。按用户指定方法组织结果，不默认一行一关，也不固定弹药、blocker、道具、28 列或前 30 关。
- 新参考 Excel 先识别其用途，再检查相关工作表、表头层级、示例行、单位、公式与图片映射。作为字段模板时保留其字段口径；只作图片或风格参考时，不强行沿用其业务字段。当前明确要求优先于模板和旧案例。
- 把用户指定图片转为可检查的取证要求：对象/事件、出现条件、时间范围、视角/区域、完整图或细节、单张或序列、保留与展示方式。优先获取这些图片；可有必要的上下文父帧，不自动扩展为整套关卡图鉴。
- 已能推断的常规选择直接执行；只有影响分析含义、计数、图片选择或验收的歧义才询问，同时继续不依赖答案的工作。需求变化时更新任务规格和映射，保留可复用的已采证据。

## 确认工具与证据标准

- 查找可用的 GameLens 工具或本地项目，核对当前接口与环境。不要假设存在已连接的 MCP，也不要把一次任务的本机路径写成所有环境的固定路径。
- 为视频及参考文件建立来源 ID、文件哈希和元数据。原视频与参考文件保持只读；在独立输出目录保存结果。
- 区分直接观察、设计解释和待核实项。参考表中的对象、数值或引入位置不代表当前游戏已证实；外观相似不代表官方名称或机制相同。仅凭视频不能回答的字段标注待核实或所需额外数据。

## 覆盖、补看与判断

1. 在请求范围内定位相关片段、对象和边界，再按任务规格取证。全面拆解先做范围覆盖；已指定时间或对象时可先定向取证。没有关卡结构时不强行划关，也不为了局部请求自动分析整段视频。
2. 依证据类型选择方法：界面/对象需要清晰静帧，操作或机制变化需要前后帧或短序列，计数需要覆盖相应范围。遇到文字不清、边界缺失或记录冲突，调整时间窗口、采样密度或空间 ROI，核对实际返回结果。
3. 用前后上下文区分任务中的真实状态及录屏播放器内容；按规格核对字段判据。例如分析关卡结果时，未拍到通关不能把最后一次 HUD 数值填成通关剩余量。截图清晰不代表机制推断已经成立。
4. 记录问题、采样参数、证据 ID、观察结果、修订和停止原因。字段和图片要求有明确答案后停止补看；无法确认或目标未出现时记录缺口，不用相似对象或参考图片代替。

## 图片归档与索引：取证后、生成报告前

从取证开始持续保存图片和索引；交付前核对归档完整性。即使用户只要 Excel，也要保留其所用图片的独立文件与来源。

执行时读取 [图片归档规范](references/image-evidence.md)，落实三部分：

- **图片本体**：保存完整原帧和裁剪图；缩略图、拼图及嵌入报告的副本不能替代它们。新采集的归档原帧尽量保留视频原生分辨率，记录实际尺寸。
- **来源记录**：证据 ID、来源 ID、视频实际时间/帧号、父原帧 ID、裁剪区域、图像文件及哈希。模板图片记录工作簿、工作表和锚点位置。
- **业务关联**：本次拆解单位、业务对象、观察角色及适用的确认状态。关卡/回合/操作阶段等由任务规格扩展，不要求所有游戏都有 blocker 或道具。同一张图可关联多个对象，不必复制成多个证据。

保存后对照完整原帧及图片要求检查裁剪：请求对象是否完整、关键文字是否可读、上下文或动作阶段是否足够。布局分析还需检查目标与平台是否被截断。遮挡或模糊时补取相邻画面，不能补画或美化成证据。

新裁剪、新标注和判断修订使用新版本或新 ID；保留父图、旧版与修订关系。后续报告先查已有索引复用，仅在证据不足时补采。

## 报告、Trace 与交付

- 按本次规格输出：例如新模板中的回合行、用户指定操作的图片序列或机制比较记录。只有任务需要时才制作逐关布局、blocker/道具图鉴或展示页；不把示例交付形式变成每次必做项。
- 图片保留证据 ID 及来源标签，区分实录、参考、标注和派生用途。保留目录与展示选择可不同，用户要求留存但不展示的图不自动嵌入报告。
- 用户所需的 Excel、展示页等交付物读取同一份任务规格和已核对的关联索引，避免各自重新截图或维护相互冲突的标签。实际读写工作簿时使用可用的电子表格 skill。
- Trace 包包含独立图片、来源清单、图片索引、业务关联、实际工具调用与必要的复现参数；使用包内相对路径。原视频是否随包提供须写明，不能暗示截图包包含原视频。
- 记录真实能力归属：GameLens 原生流程、外部 Agent 补看及语义判断分别统计。工具调用次数不等于推理轮数，也不能当成准确率或效率提升指标。Trace 保存可审计的行动与判断摘要。
- 交付前逐项核对本次字段与图片要求，列出满足、部分满足和未满足的项目及原因；检查索引引用、父原帧、来源和业务对象能闭合，图片可解码、哈希匹配、裁剪坐标有效，解压后可独立读取索引。报告渲染检查与浏览器/Excel 实际交互检查分别说明。

前 30 关中的实际经验和旧归档的字段映射见 [Smash Fest 案例](references/smash-fest-lessons.md)。处理同类关卡、裁剪修订或迁移已有 Trace 包时读取；其中的数量、时间和坐标是案例数据，不是通用参数。

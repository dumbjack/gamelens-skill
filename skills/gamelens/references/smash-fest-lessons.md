# Smash Fest 前 30 关：已验证的流程经验

来自 2026-10-12 的实际任务记录、采样脚本和 Trace 包。这里记录可迁移的方法，不把一次录屏的参数当作通用默认值。

## 拆解与取证

- 原生流程初选 48 帧不足以直接建立 30 关的完整记录。外部 Agent 增加全片覆盖，再针对开局/结束、文字、弹窗和状态冲突补看，最后为 29 个观察到的成功状态分别保留证据。
- 参考 Royal Smash 表保留 28 个字段及顺序；当前游戏的值从实录判断，参考模板只用于字段与图鉴对照。
- 播放器广告需要结合前后画面排除；L19 中心弹窗读到 Quit 后，记录为中断与重进，不能只凭弹窗形状判断为教学。
- L30 首轮失败后出现“900 金币购买 5 发”入口，随后重试，录屏在重试中结束。通关剩余弹药留空；弹窗出现不证明发生购买。

## 图片归档与裁剪

- 本次独立保存 30 张最终布局裁剪、21 张模板图（17 种 blocker、4 种道具）、8 张实录局部，连同原帧、来源和业务索引一起纳入 Trace 包。图片还能用于新报告和跨关比较。
- 最初布局裁剪的上边界为原帧高度的 0.19，部分高层布局顶部被截去。对照完整原帧后扩到 0.15，重新检查 30 张布局，并保留旧采样记录。**可迁移的规则是对照原帧检查完整性；0.15 不是其他游戏的默认边界。**
- 最终布局 ROI 为 `[0, 0.15, 1, 0.72]`，对应源画面 540×1204；新任务按实际游戏布局确定范围。
- Royal Crate 只确认外观对应，名称未证实；模板中有图而录屏未核实的项目保留“仅参考图”。Fail Offer 可记录为出现的购买入口，未见购买。

## 已有 Trace 包如何迁移

这次的归档使用分散的等价记录，而非新规范中的统一文件名：

| 已有文件 | 可复用信息 |
| --- | --- |
| `source_manifest.json` | 视频/参考工作簿路径、SHA256、视频元数据、原视频未随包提供 |
| `analysis_data.json` 的 `evidence` | 证据 ID、实际时间、region、图片相对路径与部分 OCR |
| `analysis_data.json` 的 `rows` | 关卡与开局、结束、成功等证据的关联 |
| `visual_assets.json` 的 `levels` | 最终布局图、父开局证据 ID、时间、ROI 与尺寸 |
| `visual_assets.json` 的 `catalogue` | 对象名称/类别、参考图来源、实录图及确认状态 |
| `visual_asset_evidence.json` | 8 张实录局部的证据记录 |
| `requests_visual_assets.json` / `requests_layout_images.json` | 裁剪请求、父证据 ID 与原因；包中位于 `replay/` |
| `tool_calls.jsonl` | 实际采样参数、返回证据 ID、耗时与时间 |
| `execution_journal.json` | 裁剪修订、错误恢复和验证限制 |

复用旧包时先解析这些关联即可。若需统一索引，把记录规范化到新的图片索引和业务关联文件，保留原 ID；尚未记录的图片哈希、精确帧号或独立名称状态应核实补齐或标记未知。不能声称旧包已经具备所有新字段。

## 报告与运行限制

- Excel 与 HTML 读取同一份 `visual_assets.json`，布局及图鉴按同一证据映射输出。
- 原工作簿正在被应用占用时，导出带图片的新版本并保留原文件。导出的超链接公式产生错误时改用可核对的关卡引用，再检查单元格结果。
- 此次 GameLens 使用 local 模式，内部云模型调用为 0；语义判断与额外定向采样由外部 Codex 会话完成。144 次定向采样是工具调用数量，不是准确率或推理轮数。
- 此次完成工作簿渲染与 HTML 静态检查，没有完成 Excel 桌面交互和浏览器实际交互验证。后续按实际验证情况报告，不继承为已通过。
